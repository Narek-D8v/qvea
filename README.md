# Qvea — комнаты голосований

Веб-приложение для голосований в классе или группе: одна комната с коротким кодом и QR-кодом, внутри —
сколько угодно голосований по темам. Вход через Google, результаты в реальном времени для организатора.

Всё работает на бесплатных тарифах: **Vercel** (хостинг) + **Supabase** (Postgres, Realtime, Google OAuth).
Своего сервера не нужно.

---

## Что умеет

**Комната**

- создаётся любым вошедшим пользователем;
- вход по 6-значному коду или по QR-коду/ссылке;
- необязательный лимит участников (организаторы в лимит не входят);
- несколько голосований внутри одной комнаты — повторно вводить код не нужно;
- создатель комнаты может удалить её целиком;
- организаторы добавляются по почте Google и исключаются из комнаты.

**Голосование**

- тема, описание, от 2 до 20 вариантов;
- один вариант или несколько (с ограничением максимума);
- режим **анонимный** — организатор видит только счётчики;
- режим **с именами** — организатор видит, кто как проголосовал, а участник видит предупреждение об этом
  до голосования;
- черновик / идёт / закрыто; закрытие публикует окончательные итоги всем участникам;
- живой подсчёт голосов в интерфейсе организатора;
- голос можно менять, пока голосование не закрыто;
- после первых голосов режим и правила выбора фиксируются — результаты нельзя обесценить правкой на ходу.

**Доступ**

- только через Google-аккаунт: боты и анонимные накрутки отсекаются, у каждого участника один голос;
- организатором может стать только человек, который уже входил на сайт.

**Аккаунт**

- меню в шапке (аватар и почта) с быстрым переходом в профиль, комнаты и историю;
- профиль: имя, почта и крупная аватарка из Google; можно загрузить свою (картинка сжимается в браузере);
- «Мои комнаты» — отдельный фильтр комнат, где вы создатель или организатор;
- история голосований — все опросы, в которых вы голосовали;
- выход из аккаунта с возвратом на главную.

## Как устроена приватность голосов

Это главное архитектурное решение, поэтому коротко и по делу.

- Голоса лежат в таблице `votes` (`poll_id`, `option_id`, `user_id`). `user_id` нужен, чтобы один человек
  не мог проголосовать дважды и чтобы в именном режиме показать имена.
- На таблице включён RLS. Политика `select` разрешает читать **только свои** голоса, а чужие — только
  организатору комнаты и только если голосование в режиме `identified`.
- Политик `insert` / `update` / `delete` нет вообще: клиент не может записать или подделать голос напрямую.
  Запись идёт через функцию `cast_vote` (`security definer`), которая проверяет членство, статус,
  число вариантов и принадлежность вариантов голосованию.
- В анонимном голосовании организатор получает только агрегаты через функцию `poll_results` — она
  возвращает счётчики по вариантам. Прочитать «кто за что» через приложение или API он не может.
- Realtime-сигнал идёт по таблице `poll_stats`, в которой нет личности голосующего: подписка сообщает
  «что-то изменилось», а цифры забираются через `poll_results` с проверкой прав.

**Честная оговорка.** Владелец проекта Supabase (то есть вы) технически имеет доступ к базе через SQL
редактор и в принципе может посмотреть сырые строки. Для учебного голосования этого достаточно; если
нужна криптографическая анонимность, голоса стоит вынести в отдельную таблицу с необратимыми токенами —
это отдельная задача.

## Локальный запуск

### 1. Создайте проект Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и создайте проект (Free plan).
2. Дождитесь готовности базы (1–2 минуты).
3. Из **Project Settings → API** скопируйте:
   - `Project URL` — это `NEXT_PUBLIC_SUPABASE_URL`;
   - `anon public` (в новых проектах — `publishable key`) — это `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

### 2. Примените схему базы

1. Откройте **SQL Editor → New query**.
2. Вставьте целиком содержимое файла [`supabase/schema.sql`](supabase/schema.sql) и выполните (Run).
3. Файл создаёт таблицы, RLS-политики, функции и подписки Realtime. Его можно запускать повторно.

Проверить, что всё создалось: **Table Editor** должен показать таблицы `profiles`, `rooms`,
`room_members`, `polls`, `poll_options`, `votes`, `poll_stats`.

Затем так же выполните [`supabase/avatars.sql`](supabase/avatars.sql) — он создаёт бакет `avatars`
в Storage и разрешает пользователю менять аватар в своём профиле. Без этого шага всё работает,
кроме загрузки своей аватарки.

### 3. Включите вход через Google

**В Google Cloud Console**

1. [console.cloud.google.com](https://console.cloud.google.com) → создайте проект (или выберите существующий).
2. **APIs & Services → OAuth consent screen**: тип External, заполните название и почту поддержки.
   В разделе Scopes достаточно `email` и `profile`.
3. **Credentials → Create credentials → OAuth client ID → Web application**.
4. В **Authorized redirect URIs** добавьте ровно один адрес:

   ```
   https://<PROJECT_REF>.supabase.co/auth/v1/callback
   ```

   `<PROJECT_REF>` — идентификатор проекта Supabase (он же в Project URL).
5. Скопируйте **Client ID** и **Client Secret**.

**В Supabase**

1. **Authentication → Sign In / Providers → Google**: включите провайдера и вставьте Client ID и Secret.
2. **Authentication → URL Configuration**:
   - **Site URL**: `http://localhost:3000` для разработки (потом — адрес на Vercel);
   - **Redirect URLs**: добавьте `http://localhost:3000/**` и `https://<ваш-домен>.vercel.app/**`.

### 4. Заполните переменные окружения

```bash
cp .env.example .env.local
```

```env
NEXT_PUBLIC_SUPABASE_URL=https://<PROJECT_REF>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon public key>
# необязательно, для QR-ссылок; локально определяется автоматически
NEXT_PUBLIC_SITE_URL=
```

### 5. Запустите

```bash
npm install
npm run dev
```

Откройте http://localhost:3000, войдите через Google и создайте комнату.

## Публикация на Vercel

1. Залейте проект в репозиторий GitHub:

   ```bash
   git init
   git add .
   git commit -m "Qvea: комнаты голосований"
   git branch -M main
   git remote add origin https://github.com/<username>/<repo>.git
   git push -u origin main
   ```

2. На [vercel.com](https://vercel.com) → **Add New → Project** → импортируйте репозиторий.
3. В **Environment Variables** добавьте `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   и (по желанию) `NEXT_PUBLIC_SITE_URL` с адресом будущего сайта.
4. Deploy.

После первого деплоя:

5. В **Supabase → Authentication → URL Configuration** пропишите боевой адрес:
   - Site URL: `https://<ваш-проект>.vercel.app`;
   - Redirect URLs: `https://<ваш-проект>.vercel.app/**` (localhost можно оставить для разработки).
6. Если позже подключите свой домен — добавьте его в Supabase redirect URLs и в
   `NEXT_PUBLIC_SITE_URL`, иначе вход и QR-ссылки будут вести на старый адрес.

### Чек-лист после деплоя

- [ ] вход через Google открывает страницу «Ваши комнаты»;
- [ ] создание комнаты возвращает код из 6 символов;
- [ ] QR-код открывается на телефоне и ведёт в комнату;
- [ ] второй аккаунт входит по коду и голосует;
- [ ] у организатора цифры меняются без перезагрузки страницы;
- [ ] после закрытия итоги видны участнику;
- [ ] в анонимном голосовании организатор видит только числа.

### Если сайт медленный: регион функций

Самая частая причина «тормозов» после деплоя — функция Vercel и база Supabase в разных
частях света: каждый запрос к базе идёт через океан. Проверьте регион проекта Supabase
(**Project Settings → Infrastructure**) и поставьте функцию Vercel в тот же регион:
**Project → Settings → Functions → Function Region** (например, `Frankfurt (fra1)` для
Европы). После смены региона сделайте Redeploy.

## Скорость

Что уже сделано, чтобы сайт открывался быстро:

- шрифты Onest и JetBrains Mono собираются вместе с проектом и раздаются с нашего домена —
  браузер не ждёт `fonts.googleapis.com` (из России он часто недоступен, и страница
  висела до таймаута) и не открывает лишних соединений;
- пользователь определяется один раз на запрос через `getClaims`: для проектов с
  асимметричными ключами подписи JWT проверяется локально, без похода в Supabase Auth.
  Шапка и страница делят один результат, а имя и аватар берутся из JWT — запрос к
  `profiles` больше не нужен;
- анонимные запросы вообще не трогают Supabase: в proxy стоит быстрый выход по
  отсутствию cookie сессии;
- запросы к базе идут пакетами (`Promise.all`) вместо последовательных ожиданий:
  страница голосования укладывается в 3–4 круга до базы вместо 8;
- счётчик участников берётся через `count` — в ответе нет самих строк;
- пакет `@electric-sql/pglite` (нужен был только для проверки схемы) убран из
  зависимостей, поэтому установка и сборка на Vercel быстрее.

## Структура проекта

```
app/
  page.tsx                      лендинг и вход
  join/page.tsx                 вход по коду
  rooms/page.tsx                список комнат, создание, вход по коду
  profile/page.tsx              профиль: имя, почта, аватар
  history/page.tsx              история голосований
  r/[code]/page.tsx             комната: голосования, QR, участники
  r/[code]/settings/page.tsx    настройки: название, лимит, организаторы, удаление
  r/[code]/polls/new/page.tsx   создание голосования
  r/[code]/p/[pollId]/page.tsx  голосование: формы, результаты, управление
  r/[code]/p/[pollId]/edit/     редактирование
  actions/                      серверные действия (rooms.ts, polls.ts, profile.ts)
  auth/                         login / callback / logout
components/                     шапка, QR, формы, живые результаты
lib/supabase/                   клиенты (браузер, сервер, proxy, route)
proxy.ts                        обновление сессии и защита приватных страниц
supabase/schema.sql             вся база: таблицы, RLS, функции, realtime
supabase/avatars.sql            бакет аватаров и право менять свой профиль
```

### Основные функции базы

| Функция | Что делает |
| --- | --- |
| `create_room` / `update_room` / `delete_room` | комната и её настройки |
| `join_room` | вход по коду с проверкой лимита |
| `add_room_admin` / `remove_room_member` | организаторы и участники |
| `create_poll` / `update_poll` / `set_poll_status` / `delete_poll` | голосования |
| `cast_vote` | атомарная запись голоса со всеми проверками |
| `poll_results` | счётчики (организатору всегда, участникам после закрытия) |
| `identified_ballots` | «кто как голосовал» — только именной режим и только организатору |

## Ограничения бесплатных тарифов

- **Supabase Free**: 500 МБ базы, до 50 000 активных пользователей в месяц. Проект засыпает после
  недели без запросов — перед уроком достаточно открыть сайт или панель Supabase, чтобы разбудить его.
- **Vercel Hobby**: бесплатно для личных и некоммерческих проектов; для школьного голосования подходит.
- **Google OAuth**: бесплатно, но при статусе приложения *Testing* войти смогут только добавленные
  тестовые пользователи (до 100). Для класса это удобно; чтобы пускать любой Google-аккаунт, переведите
  приложение в *In production*.

## Возможные проблемы

| Симптом | Причина |
| --- | --- |
| `redirect_uri_mismatch` при входе | в Google OAuth не добавлен `https://<PROJECT_REF>.supabase.co/auth/v1/callback` |
| после входа снова лендинг | адрес сайта не добавлен в Supabase → Authentication → URL Configuration |
| «Не заданы NEXT_PUBLIC_…» | нет `.env.local` (локально) или переменных в Vercel |
| результаты не обновляются сами | таблица `poll_stats` не попала в публикацию `supabase_realtime` — перезапустите `schema.sql` |
| `relation "public.rooms" does not exist` | схема не применена в SQL Editor |
